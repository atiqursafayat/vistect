# Vistect — Full-Spec Engineering Execution Plan

**Goal:** Build Vistect complete per vistect_pts.md — a WebMCP-native, local-first, WCAG 2.2 AA visual document workspace for blind/low-vision authors — producing all planning artifacts first, then implementing phase-by-phase with tests, accessibility, type safety, security, and validation on every feature. No placeholders, no TODOs, no mock production code.

## Locked Architectural Decisions (ADRs to be written in Phase 0)

1. **Agent-as-Analyst, zero backend** (user-confirmed): No built-in AI provider, no API keys, no server. Deterministic analysis (PDF text via PDF.js, image metadata, geometry, topology, contrast, chart-data equality) runs locally in-browser. Interpretive analysis (image descriptions, alt text, tone, diagram reconstruction) is performed by the user's browser agent via schema-structured tool round-trips (`inspect_image` → agent reasons → `record_image_analysis` with forced observations/interpretations/uncertainties arrays → staged as human-approved decision). UI renders visuals for agent screenshot inspection while exposing semantics for screen readers. R2 extension point: pluggable remote-provider adapter (documented, not built).
2. **Pure static SPA**: Vite + React 19 + TypeScript (strict, zero `any`) deployed to Vercel (hosted live URL per hackathon rules; public GitHub repo, MIT license). SSR adds nothing to an IndexedDB local-first app.
3. **Deterministic client-side PDF export** (user-confirmed): pdf-lib renderer driven by the same layout engine that powers preview + geometry validation → provable version binding via hashes.
4. **Single command bus**: ALL mutations (UI, WebMCP tools, import) flow through one command layer: Zod validation → optimistic version check (`expectedDocumentVersion`) → domain state machines → event append → validation recompute → decision-ledger entry → live-region announcement. Sole write path = provable audit trail.
5. **Zod as schema source of truth**: WebMCP `inputSchema` JSON Schemas compiled from Zod (zod-to-json-schema) — tool contracts and runtime validation can never drift.
6. **Event-sourced domain core** (pure TS package, zero React/DOM deps): version = event count; stale approvals/topology checks = event reactions; undo = event logic; snapshots for compaction.
7. **Hand-rolled transition tables** (not XState) for document/approval lifecycles — exhaustive switch + tests; **custom SVG chart renderer** (3 chart types only; exact geometry needed for integrity checks) over Vega-Lite; **ELK.js** (lazy-loaded, dagre fallback) for diagram layout; **DOMPurify + custom allowlist** for SVG sanitization; **Zustand** for view-state projection; **PDF.js** for import.
8. **WebMCP integration**: thin adapter over `document.modelContext.registerTool` with capability detection + graceful degradation (manual UI parity when no agent); tools registered incrementally per module from Phase 1; `use-webmcp-tool` evaluated for React binding in ADR.

## Phase 6 — WebMCP Hardening
